# Known Gaps — Read Before You Trip Over Them

**Current state.** Real, current, and they bite silently. Each row names the file that proves it. And when a gap is closed, just add ***Closed.*** to indicate it's closed.

| 13 | **Two specs fail intermittently on full runs because their ARRANGEMENT assumes an idle machine — and neither is gap #7.** `ingestion-pipeline` 6c and `realtime` Presence 5. Both fail only on a full run and that is where the resemblance stops. #7 asserts BullMQ queue isolation against a **shared real Redis** — genuine cross-suite interference. 6c hangs a `downloadObject` promise it owns and then `waitFor`-polls **its own job row in Postgres** until the status reads `PARSING`; it touches no queue and opens no Redis connection. Its failure is a **poll budget sized for an idle process**, expiring when `--runInBand` gives the box more to do. One sighting each, in two services. | `apps/ingestion-service/test/modules/ingestion-pipeline.e2e-spec.ts` (6c), `apps/api-gateway/test/modules/realtime.e2e-spec.ts` (Presence 5), `realtime.gateway.ts` (`announceConnected`), `@synapsedesk/common/testing/wait` | Filed separately on purpose: merging it into #7 would point the next person at Redis for a test that never opens a connection to it, and merging two rows later is cheap while un-merging a generalization that has already sent somebody to the wrong system is not. **SECOND SIGHTING, CAPTURED (doc 49 validation), different spec, mechanism identified.** `realtime.e2e-spec` Presence 5 expected `away` and got `online`. `announceConnected` broadcasts `online` to `org:{id}` whenever a connecting client's state CHANGES, and the test connects three clients before registering its listener — so `colleague` receives its own connect-time `online`. On an idle machine those broadcasts land before `waitForEvent` registers; under a full run they can land after, and the listener resolves with the wrong event. Same class as 6c: **a test whose arrangement assumes the machine is idle**, not cross-suite interference — no shared state is involved in either. **Fix shape (both):** make the arrangement wait for the thing it is racing rather than assume it has already happened — drain connect-time presence before listening; widen or remove 6c's poll budget. **Next sighting, capture before re-running:** the elapsed time at failure and what else was running. Note #7's capture instruction is scoped to one spec, which is probably the bug — the information it protects (which suites were in the run) is lost either way. |
| 14 | **A suite that tears down shared broker state can fail an unrelated service's suite mid-run — a third distinct class from #7 and #13.** Caught during doc 50, not in the wild: `jetstream-bootstrap.e2e-spec` deleted the real `AUDIT` and `NOTIFICATIONS` streams in `afterAll`, and ticket-service's audit suite failed with `NatsError: stream not found` on every test. Both halves of the rule are load-bearing: leaving shared state alone is not the same as leaving YOUR state behind. |
