# Known Gaps — Read Before You Trip Over Them

**Current state.** Real, current, and they bite silently. Each row names the file that proves it. Verify before trusting; delete the row when you close it.

| # | Gap | Where | Consequence |
| :---- | :---- | :---- | :---- |
| 1 | **Tenant scoping is applied by hand.** `tenantScope()` is the shared helper and is used across services, but there is **no Prisma middleware or `$extends`** — nothing forces a query to call it. | `libs/common/src/utils/tenant-scope.ts` | A forgotten `...tenantScope(ctx)` is a cross-tenant data leak, not a bug. **`findUnique({ where: { id } })` cannot express the filter at all** — always `findFirst` + scope, and let a miss be `NOT_FOUND`, never `PERMISSION_DENIED`. |
| 2 | **`otps.code_hash` and `two_factor_backup_codes.code_hash` use SHA-256** where a slow KDF is the better fit (§8.1). Both columns are already `VarChar(255)` to accommodate one. | `apps/auth-service/src/modules/otp/otp.service.ts` (`hashToken(code)`), `apps/auth-service/src/common/utils/crypto.ts` | A 6-digit code is ~20 bits — offline-guessable if the table leaks. `maxAttempts` + short expiry are the online defence today. |
| 3 | **Deferred ingestion jobs are never resumed.** When a tenant hits the AI cap mid-ingestion the processor returns the job to `QUEUED` and the document to `PENDING`, and the BullMQ job completes successfully — deliberately, so the deferral does not burn the retry budget. `drainDeferred()` exists to re-enqueue them at cycle roll and **has no caller**. | `apps/ingestion-service/src/modules/ingestion/ingestion-queue.service.ts` (`drainDeferred`), `ingestion.processor.ts:190` | A document deferred at the cap stays `PENDING` and unindexed forever. `POST /ingestion-jobs/:id/retry` is the manual hatch; nothing automatic exists. |
| 4 | **Nothing enforces "at most one live ingestion job per document."** Retry claims the *source row* (`ingestion_jobs.superseded_by_id`), so two clicks on one row cannot both win — but two clicks on **two different terminal rows of the same document** both succeed, and so would any second re-enqueue path. The invariant wants a partial unique index on `(document_id) WHERE status IN ('QUEUED','PARSING','CHUNKING','EMBEDDING')`, which Prisma cannot express — it needs raw DDL in the seeder, a third exception to `development-conventions.md` §7. | `apps/ingestion-service/src/modules/ingestion-jobs/ingestion-jobs.service.ts` (`retryIngestionJob`), `ingestion.processor.ts` (`writeChunkRows`) | Two workers on one document interleave `deleteMany`/`createMany` on its chunks, leaving the first set's vectors orphaned in Qdrant with no row pointing at them — the outcome `writeChunkRows`'s docblock says `deleteMany` exists to prevent. Deliberately deferred until `POST /documents/:id/reindex` needs the same guard on a second route. |
| 5 | **The `users` super-admin CHECK constraint was never applied.** `apps/auth-service/prisma/schema.prisma:151` says `organization_id` is *"kept in lockstep with isSuperAdmin by a DB CHECK constraint added via migration: (organization_id IS NULL) = is_super_admin"*, and `development-conventions.md` §7 names it as one of two things needing hand-written SQL. There are no migrations, and the seeder's DDL block creates exactly one CHECK on `users` — `users_locked_until_requires_lock` — which is a different constraint. | `apps/auth-service/prisma/schema.prisma:151`, `apps/auth-service/src/modules/prisma/database.seeder.ts` (the raw-DDL block), `docs/development-conventions.md` §7 | Nothing prevents `organization_id = NULL` with `is_super_admin = false`: a row with no tenant that is not a platform account, which every tenant filter treats as unreachable rather than as an error. Any code reasoning "super admins have no tenant" — e.g. the `!== undefined` guard in `AuditPublisher.record` — is relying on convention, not on the database. |
| 6 | **`?search=` is advertised on five list routes and honoured on none of them.** `SearchPaginationDto` puts `searchTerm` on the wire and into Swagger, but `toSearchFilter(page.searchTerm)` is called in exactly two services — `documents.service.ts:314` and `tickets.service.ts:120`. The DTOs for ingestion jobs, document flags, audit logs, ticket messages and feedback all extend it and all ignore it. | `apps/api-gateway/src/common/dto/rest/search-pagination.dto.ts` (the base), and the five `List*QueryDto` classes extending it | A caller filters a worklist by `?search=`, gets an unfiltered page back, and reads it as "no other matches exist". Silently dropping a documented filter answers a different question than the one asked — the failure `listDocumentFlags` explicitly refuses an unknown flag type to avoid. |
| 7 | **`scheduler-ownership.e2e-spec` fails intermittently on a full auth-service run.** Three sightings across three docs, each on `npm run test:e2e:auth` with every other suite in the run, each passing in isolation on the next attempt, and each with the session's changes nowhere near a scheduler. The suite asserts BullMQ queue isolation against a **shared real Redis**, and every service's e2e suite uses the same instance — `bootstrap.ts` already documents the class of problem for ingestion ("WORK must not escape its test"). | `apps/auth-service/test/modules/scheduler-ownership.e2e-spec.ts`, `apps/auth-service/test/utils/bootstrap.ts` | A red suite that is green on re-run teaches the team to re-run. **Next sighting, capture before re-running:** which case failed, whether another suite in the same run had touched `SCHEDULER_QUEUE`, and the Redis key set at failure — three sightings with no captured detail is why this is still a maybe. |
| 8 | **Three writes move `roles.user_assigned` without evicting the cache that shows it.** `GET /roles` caches `userAssigned` for five minutes per tenant. `PUT /users/:id/roles` and `DELETE /users/:id` now evict it; **`POST /invitations/accept` cannot** — `CacheInvalidationInterceptor` derives the tenant from the request context and returns early without one, and that route is unauthenticated by design. | `apps/api-gateway/src/modules/invitations/invitations.controller.ts` (`accept`), `apps/api-gateway/src/common/interceptors/cache-invalidation.interceptor.ts` | After an invitation is accepted, the roles screen shows a stale `userAssigned` for up to five minutes, and a cached hit is indistinguishable from a fresh read. Covered by TTL, which is the same trade that interceptor already accepts for a platform Super Admin writing into a tenant. Closing it needs an eviction path that does not depend on a caller — the NATS consumer that class mentions. |
| 9 | **The export family is named for one of its four kinds.** `AnalyticsExport`, `analytics_exports`, `AnalyticsExportKind`, `ANALYTICS_EXPORT_QUEUE` and `apps/ticket-service/src/modules/analytics/analytics-export.*` now carry `TICKET` and `AUDIT_LOG` exports, which read live tables and are not analytics. The shared thing is the LIFECYCLE — one status machine, one queue, one processor, one poll route — which is why they share a table rather than getting two more. | `libs/common/src/configs/analytics.config.ts` (`AnalyticsExportKind`), `apps/ticket-service/prisma/schema.prisma` (`AnalyticsExport`) | A reader looking for the ticket export finds it under analytics, and a table called `analytics_exports` holds audit-log rows. Renaming to `Export` is ~18 files outside generated code plus a proto regeneration and the enum-bridge registry — deferred deliberately, not overlooked. Do it as its own change, or the half-done state sits under three features. |
