# Known Gaps — Read Before You Trip Over Them

**Current state.** Real, current, and they bite silently. Each row names the file that proves it. Verify before trusting; delete the row when you close it.

| # | Gap | Where | Consequence |
| :---- | :---- | :---- | :---- |
| 1 | **Tenant scoping is applied by hand.** `tenantScope()` is the shared helper and is used across services, but there is **no Prisma middleware or `$extends`** — nothing forces a query to call it. | `libs/common/src/utils/tenant-scope.ts` | A forgotten `...tenantScope(ctx)` is a cross-tenant data leak, not a bug. **`findUnique({ where: { id } })` cannot express the filter at all** — always `findFirst` + scope, and let a miss be `NOT_FOUND`, never `PERMISSION_DENIED`. |
| 2 | **`otps.code_hash` and `two_factor_backup_codes.code_hash` use SHA-256** where a slow KDF is the better fit (§8.1). Both columns are already `VarChar(255)` to accommodate one. | `apps/auth-service/src/modules/otp/otp.service.ts` (`hashToken(code)`), `apps/auth-service/src/common/utils/crypto.ts` | A 6-digit code is ~20 bits — offline-guessable if the table leaks. `maxAttempts` + short expiry are the online defence today. |
| 3 | **Deferred ingestion jobs are never resumed.** When a tenant hits the AI cap mid-ingestion the processor returns the job to `QUEUED` and the document to `PENDING`, and the BullMQ job completes successfully — deliberately, so the deferral does not burn the retry budget. `drainDeferred()` exists to re-enqueue them at cycle roll and **has no caller**. | `apps/ingestion-service/src/modules/ingestion/ingestion-queue.service.ts` (`drainDeferred`), `ingestion.processor.ts:190` | A document deferred at the cap stays `PENDING` and unindexed forever. `POST /ingestion-jobs/:id/retry` is the manual hatch; nothing automatic exists. |
| 4 | **Nothing enforces "at most one live ingestion job per document."** Retry claims the *source row* (`ingestion_jobs.superseded_by_id`), so two clicks on one row cannot both win — but two clicks on **two different terminal rows of the same document** both succeed, and so would any second re-enqueue path. The invariant wants a partial unique index on `(document_id) WHERE status IN ('QUEUED','PARSING','CHUNKING','EMBEDDING')`, which Prisma cannot express — it needs raw DDL in the seeder, a third exception to `development-conventions.md` §7. | `apps/ingestion-service/src/modules/ingestion-jobs/ingestion-jobs.service.ts` (`retryIngestionJob`), `ingestion.processor.ts` (`writeChunkRows`) | Two workers on one document interleave `deleteMany`/`createMany` on its chunks, leaving the first set's vectors orphaned in Qdrant with no row pointing at them — the outcome `writeChunkRows`'s docblock says `deleteMany` exists to prevent. Deliberately deferred until `POST /documents/:id/reindex` needs the same guard on a second route. |
